# Project S - Task Manager

A mobile-first web app for entering and managing task data backed by a Google Sheet.
Runs entirely as a static site (no build step) - open `index.html` in any browser.

## Structure

```
project-s/
  index.html            App shell (4 views: Dashboard, Tasks, Organizations, Settings)
  css/styles.css        Mobile-first styling
  js/api.js             API client: Apps Script (read/write), live sheet (read), demo
  js/app.js             UI logic, rendering, formatting
  appsscript/Code.gs    Google Apps Script backend (paste into your sheet)
```

## Sheet structure the app expects

The task sheet columns (from the provided spreadsheet):

```
No | Task-ID | Task name | Purpose | PIC | Organization | Date | Due Date | Value | Note | Internal | Duration | Status
```

The **Organization** sheet supplies the `Name` column used for the organisation lookup.

## Two connection modes

### 1. Live sheet (read-only, out of the box)

The app ships with your spreadsheet URL preconfigured, so it connects to the live
sheet immediately (view mode). Because the sheet is publicly viewable, the app reads it
directly in the browser via Google's data endpoint.

### 2. Apps Script backend (add / edit / delete)

To enable writes, deploy the included backend:

1. Open your sheet: **Extensions > Apps Script**.
2. Replace the default code with the contents of `appsscript/Code.gs`, then **Save**.
3. **Deploy > New deployment > Web app**:
   - Description: `Project S API`
   - Execute as: **Me** (authorises access to the private sheet)
   - Who has access: **Anyone**
4. Copy the `.../exec` URL.
5. In the app, open **Settings**, paste the URL, tap **Test Connection**.

The backend reads the **current dropdown (data validation)** options for Purpose, PIC and
Status straight from the sheet, looks up organisations from the **Organization** sheet's
**Name** column, and performs add / update / delete on the task sheet.

Clearing both URLs in Settings switches the app to **demo mode** (sample data).

## Features

- **Dashboard** - total task count plus per-status counts (cards + distribution bars).
  Tap a status card/bar to jump straight to the filtered task list.
- **Tasks** - searchable list, filter chips by status, an **Internal** filter
  (All / Internal / External), colour-coded status badges, overdue due dates highlighted.
- **Add / Edit / Delete** - floating + button opens the form; each row has Edit and Delete.
  `No` is hidden in the form and auto-generated by the backend; `Task-ID` is **disabled**
  and auto-filled by the sheet's own formula (the app never writes it).
- **Date & Due Date** - native calendar picker; displayed as `dd-mmm-yy` (e.g. 09-Aug-26),
  overdue due dates highlighted.
- **Value** - numeric, right-aligned, formatted with thousand separators.
- **Purpose / PIC / Status** - dropdowns synced live from the sheet's validation rules.
- **Organization** - a dropdown menu fed by the Organization sheet `Name` column (same style
  as the PIC dropdown).
- **Organizations view** - dedicated maintenance menu to **add / edit / delete** organisations
  (each with its own confirmation dialog).
- **Duration** - display-only (read-only) field; the value is computed by the sheet's formula,
  which the backend copies from the last row whenever a new task is added. In the task list it
  is shown bold **red** when the text contains "overdue", otherwise **blue**.
- **Dashboard colours** - status cards/bars are colour-coded; `Hold` renders brown and `Urgent`
  renders red.
- **Note / Internal** - full support for the remaining task columns.
- **Security** - Settings are locked by default with a **default password `00000`**; the
  Spreadsheet / Apps Script links stay hidden until unlocked. Use the "Lock Settings" section
  to change the password (stored as a hash).

Clearing both URLs in Settings switches the app to **demo mode** (sample data).

## Backend API

The Apps Script exposes these actions (JSON):

| Action | Method | Parameters |
| ------ | ------ | ---------- |
| `init` | GET | - |
| `tasks` | GET | - |
| `add`  | POST | `{ action, fields }` |
| `update` | POST | `{ action, row, fields }` |
| `delete` | POST | `{ action, row }` |
| `ping` | GET | - |
| `orgs` | GET | - |
| `addOrg` | POST | `{ action, name }` |
| `updateOrg` | POST | `{ action, row, name }` |
| `deleteOrg` | POST | `{ action, row }` |

Organisation records are `{ row, No, Name }` so maintenance can address exact sheet rows.

On `add`, the backend auto-generates `No` (max + 1) and copies any sheet formulas
(e.g. `Task-ID`, `Duration`) from the last row into the new row. Formulas are copied
with **relative references adjusted** to the new row (via `copyTo` + `PASTE_FORMULA`),
so they stay dynamic; `Task-ID` and `Duration` are never written by the app.
